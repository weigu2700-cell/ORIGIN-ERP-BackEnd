# ORIGINERP

ORIGINERP 是一个面向中小型制造企业的轻量级 ERP 项目，围绕 **销售、采购、库存、BOM、生产、组织权限** 等核心业务进行设计与实现。

项目采用前后端分离架构，目标不是简单实现后台 CRUD，而是通过真实制造业业务场景，逐步构建一套包含 **Web ERP、PDA 现场作业端、小程序移动端、零代码表单平台以及 AI 智能助手** 的完整企业数字化系统。

---

## 项目背景

制造企业中的销售、库存、采购和生产通常存在较强的业务关联。

例如一张销售订单可能会触发：

```text
销售订单
    ↓
成品库存检查
    ↓
库存预留
    ↓
库存不足
    ↓
生成生产需求
    ↓
BOM 展开
    ↓
计算原材料缺口
    ↓
采购补料
    ↓
采购入库
    ↓
生产领料
    ↓
生产报工
    ↓
成品入库
    ↓
销售出库
```

SmartERP 重点解决各业务模块之间数据割裂、库存状态不透明、生产与采购缺乏联动以及现场作业数字化程度不足等问题。

## 3. 库存管理

库存模块采用：

```text
On Hand   = 实际库存
Reserved  = 已预留库存
Available = On Hand - Reserved
```

销售订单确认时不会直接扣减真实库存，而是首先进行库存预留。

主要库存操作：

- 库存预留
- 库存释放
- 销售出库
- 采购入库
- 生产领料
- 生产退料
- 成品入库
- 库存调整
- 库存调拨
- 库存盘点

并通过库存流水记录每次库存变化。

```text
业务类型
业务单号
物料
仓库
变化数量
变更前库存
变更后库存
操作时间
```

库存修改与流水记录处于同一事务中。

---

## 4. 库存并发控制

针对多个订单同时操作相同库存的场景，引入：

- MyBatis-Plus `@Version`
- 乐观锁
- 有限次数重试机制
- 库存合法性校验

库存需要始终满足：

```text
onHand >= 0

reserved >= 0

reserved <= onHand
```

用于避免：

- 超卖
- 重复扣减
- 并发覆盖
- 库存数据不一致

## 5. 销售管理

销售模块负责销售订单及库存联动。

核心流程：

```text
创建销售订单
    ↓
DRAFT
    ↓
确认订单
    ↓
检查可用库存
    ↓
预留库存
    ↓
CONFIRMED
    ↓
销售出库
    ↓
COMPLETED
```

订单取消时释放已经预留的库存。

销售订单采用订单头 + 订单明细结构，并支持：

- 客户
- 物料
- 仓库
- 数量
- 单价
- 金额
- 交货日期
- 订单状态
- 订单流水号

销售订单号通过 Redis 原子自增生成，例如：

```text
SO202608310001
SO202608310002
SO202608310003
```

# Redis 使用场景

项目通过 Spring Data Redis 根据真实业务需求逐步引入 Redis，而不是单纯为了使用技术。

当前及规划使用场景包括：

### 业务流水号

通过 Redis `INCR` 原子操作生成：

- 销售订单号
- 采购订单号
- 生产工单号
- 入库单号
- 出库单号

### 幂等控制

用于防止：

- 重复提交订单
- PDA 重复扫码
- 网络重试导致重复业务操作

### 热点数据缓存

后续可用于：

- 用户权限
- 菜单
- 物料
- 仓库
- 高频基础资料

# AI Assistant

SmartERP 后续将接入 AI 助手，使 AI 能够理解真实 ERP 数据，而不仅仅是提供聊天功能。

例如用户可以询问：

```text
今天哪些销售订单可能延期？

哪些物料低于安全库存？

M001 为什么出现库存不足？

当前有哪些生产工单存在缺料？

本周采购金额是多少？
```

AI 将通过系统业务接口获取：

```text
销售订单
库存
采购
生产计划
BOM
采购在途
```

并综合分析后生成业务回答。

未来还计划支持自然语言操作：

```text
“查询今天低于安全库存的物料”

“生成 M001 的采购需求”
```

涉及数据修改的操作必须经过：

```text
AI 生成操作
     ↓
用户确认
     ↓
权限验证
     ↓
业务校验
     ↓
执行
```

避免 AI 直接修改核心 ERP 数据。

# 项目亮点

### 制造业完整业务闭环

项目不是多个独立 CRUD 模块的组合，而是围绕：

```text
销售
 ↓
库存
 ↓
生产
 ↓
BOM
 ↓
采购
 ↓
生产执行
 ↓
成品入库
 ↓
销售出库
```

构建跨模块业务联动。

### 库存一致性设计

采用：

```text
OnHand
Reserved
Available
```

库存模型，并通过：

- 乐观锁
- 有限重试
- 事务
- 库存流水

解决库存并发修改及追溯问题。

### BOM 与物料需求

通过多级 BOM 展开、库存及采购数据计算真实物料缺口，为后续实现轻量级 MRP 提供基础。

### 多终端协同

系统最终将覆盖：

```text
Web ERP
+
PDA
+
小程序
```

分别服务管理计划、现场执行和移动办公场景。

### 零代码扩展能力

通过动态表单定义和数据存储，使非核心业务可以通过配置快速扩展，降低重复开发成本。

### AI 与 ERP 业务结合

AI 不仅提供聊天能力，还计划结合销售、库存、采购、生产等真实业务数据，实现自然语言查询、风险分析和辅助决策。
