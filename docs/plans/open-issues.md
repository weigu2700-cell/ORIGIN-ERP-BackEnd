## #1：一租户一库

### 当前实现与缺口

- [`DataSourceConfig`](../../src/main/java/org/smart/erp/common/config/DataSourceConfig.java) 只有一个 Hikari 数据源，没有租户注册表或路由。
- [`JwtUtil`](../../src/main/java/org/smart/erp/common/security/JwtUtil.java) 的 subject 只有用户 ID；[`CurrentUser`](../../src/main/java/org/smart/erp/common/security/CurrentUser.java) 没有租户身份。
- [`MenuRedis`](../../src/main/java/org/smart/erp/system/cache/MenuRedis.java)、[`PermissionsRedis`](../../src/main/java/org/smart/erp/system/cache/PermissionsRedis.java)、[`BOMRedis`](../../src/main/java/org/smart/erp/production/cache/BOMRedis.java) 和业务单号/分布式锁没有统一的租户维度。
- [`WebSocketSessionManager`](../../src/main/java/org/smart/erp/common/websocket/WebSocketSessionManager.java) 用用户 ID 索引连接；不同库中的同 ID 用户会存在混淆风险。
- 基础建表与既有生产领料迁移包含固定库名 `smart-erp`。只切换数据源不会让这些 SQL 自动作用于租户库。
- AI 对话归属、工具查询、SSE、通知发布和事务完成后的回调，都必须携带或恢复租户上下文。

这些是改造前需要覆盖的边界；当前单企业部署不因此被判定存在跨租户故障。

### 建议拆分为五个可验收变更

| 顺序 | 交付内容 | 验收标准 |
| --- | --- | --- |
| T1 租户登记与开通 | 平台主库保存租户编码、启停状态、数据库连接引用、schema 版本和开通状态；平台管理员与租户管理员区分；凭据通过密钥引用读取 | 同一开通请求可重试；失败租户不会进入可用状态；业务账号不能读取其他租户连接信息 |
| T2 身份与数据源路由 | 登录先解析租户，再在目标库认证；签名 Token 绑定租户和用户；请求到达业务事务前设置路由，结束时清理；停用/未知租户拒绝访问 | 两库均有 `userId=80001` 时互不访问；篡改请求头不能切换 Token 所属租户；缺失租户不回退默认库；事务中不能切库 |
| T3 schema 生命周期 | 建立不限定固定库名的租户库初始化入口；每库独立 Flyway 历史；权限/菜单公共 seed 与开发账号分开；现有单企业库注册为首个租户 | 新租户无需手改 SQL；逐库迁移失败可定位并重试；原有迁移校验与业务数据保持完整 |
| T4 缓存与异步隔离 | Redis 缓存、锁、单号、WebSocket、AI 会话/记忆及工具、SSE 和事务回调统一使用租户上下文；异步显式传递并清理 | 相同用户/物料/订单 ID 不串缓存、不串锁、不串消息；线程复用和流式请求结束后无上下文残留 |
| T5 运维与兼容 | 限制每租户连接池及总连接数；空闲池回收；按租户备份恢复、迁移状态、审计及指标；支持显式单企业模式 | 两个租户并发读写隔离；一个库宕机不影响另一库；单企业原部署回归通过 |

建议新增 `tenant` 模块，将平台注册、路由和租户上下文放在该模块，不散落在各业务 Controller。
平台事务与租户业务事务分别定义，避免把跨库操作误认为本地事务可以原子提交。

已在既有库执行的迁移应保持不可变；不能直接改旧迁移中的库名再让现有库运行。T3 需针对新租户建立初始化基线，保留既有库历史，再使用经验证的后续迁移路径。

### 取舍与实施入口

按 Issue 评论优先规划分库：隔离、单租户恢复较直接，但连接池、批量升级和运维成本更高。
共享库加 `tenant_id` 会减少数据库数量，却要求所有查询、唯一约束与关联都正确包含租户条件；不作为这份分库计划的混合实现。
建议第一步交付 T1/T2 的双库集成测试和设计，再推进 schema 与异步隔离。完成 T1/T2 不能宣称整个 Issue 已解决。

## #2：商城小程序与 AI

### 已有能力和不可直接复用的部分

- [`AiAssistantController`](../../src/main/java/org/smart/erp/ai/controller/AiAssistantController.java) 已提供普通/流式对话，[`AiQueryTools`](../../src/main/java/org/smart/erp/ai/config/AiQueryTools.java) 已注册库存、销售、生产、采购、通知查询工具。
- [`AiConversationServiceImpl`](../../src/main/java/org/smart/erp/ai/service/impl/AiConversationServiceImpl.java) 校验用户对话归属。因此“内部 AI 集成”已有实现；本轮没有调用真实模型服务，不将其标记为模型联调验收完成。
- [`Material`](../../src/main/java/org/smart/erp/master/entity/Material.java) 是 ERP 物料，不包含商城所需的上架、展示、售价等完整商品模型。
- [`Customer`](../../src/main/java/org/smart/erp/master/entity/Customer.java) 是客户主档，不是消费者登录账号；[`SalesOrder`](../../src/main/java/org/smart/erp/sales/entity/SalesOrder.java) 有客户归属，但现有员工 API 不等于客户本人订单 API。
- 配套移动端目前服务于员工现场作业；支持编译微信小程序不代表已具备商城用户流程。

### 建议首版范围

商品展示 → 客户登录 → 购物车 → 提交订货需求 → 员工审核并进入现有销售流程 → 本人历史订单；增加只读商品查询 AI。
建议首版先采用人工确认的 B2B 订货方式，在线支付、退款、促销和物流轨迹另立需求。该边界是计划建议，实施前需确认；不将未做支付的版本描述为完整电商交易平台。

| 顺序 | 交付内容 | 验收标准 |
| --- | --- | --- |
| C1 商品目录 | 新增独立商品发布模型关联 ERP 物料，定义上下架、公开名称/图片/规格、SKU 和展示价格；提供后台发布与客户只读 DTO | 下架商品不可下单；原材料、供应商、成本及内部备注不会随商品接口返回 |
| C2 客户身份 | 独立客户账号与身份类型，绑定 `md_customer`；设计微信登录/账号登录的凭据处理和访问规则 | 客户 Token 不能进入 ERP 员工接口；客户只能读取本人资料与订单；企业客户多个联系人归属有明确规则 |
| C3 购物车与订货 | 购物车、价格快照、订货请求和请求幂等键；后端重算有效商品与价格；员工审核后通过现有销售服务建单 | 重复提交只生成一份需求及对应销售单；客户端改价无效；失败回滚；按既有销售确认流程预留库存，不在购物车阶段扣库存 |
| C4 小程序页面 | 独立商城入口，商品列表/详情、购物车、登录、提交结果、本人历史订单/详情；补齐空态和异常重试 | 真机完成全流程；登录过期有恢复路径；确认按钮重复点击不重复下单；历史订单按客户过滤 |
| C5 外部商品 AI | 独立提示词、工具白名单、会话身份和接口；仅查已发布商品、公开价格及允许公开的可售说明；订单查询仍校验本人归属 | 不注册内部采购/生产/通知工具；诱导查询成本或他人订单无数据返回；模型不可用时商品浏览和下单仍可用 |

建议后端新增 `commerce` 模块，先确定 API 契约再制作小程序页面；客户登录不能仅靠扩大现有 `/auth/login` 权限来复用员工身份。
首版提交订货需求时不提前承诺实时库存，员工确认进入销售链路时沿用库存预留校验。若产品要求即时占库存或在线支付，需要重新定义超时释放、取消和支付回调状态机。

### 与多租户的关系

商城可先在现有单企业模式下交付，避免将 #2 完全阻塞在 #1 之后。先约定身份类型、租户解析接口和缓存键组成；若部署 SaaS，必须在服务端完成租户识别，不能信任客户端传入任意库名或客户 ID。

## 回归与发布约束

- #4 的隔离回归入口：[`sql/bootstrap/test_seed.py`](../../sql/bootstrap/test_seed.py)。仅在临时 MySQL 容器创建数据。
- #1 使用两个真实 MySQL schema、相同业务 ID 和并发请求验收，覆盖事务、Redis、通知、AI 与连接池故障。
- #2 使用两个客户和一个员工验收权限边界、重复下单与价格校验，AI 工具可以用确定性模型桩测试，另设真实模型联调。
- 功能提交按以上 T/C 阶段拆分；只有验收完成的部分才能标注完成。提交、推送和 Issue 状态分别记录，不能用本地提交代替远端已发布。
