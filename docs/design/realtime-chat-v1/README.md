## 结论

可以完成。现有 Spring WebSocket、JWT、租户执行上下文、MySQL、Redis 和 Flyway 可复用。新增 `im` 模块，与已有 AI 对话和 EIP 业务通知分别存储、分别定义协议。

推荐沿用当前后端自部署：REST 可靠写入/查询，WebSocket 实时推送，MySQL 保存消息和补偿事件，私有 S3 兼容对象存储保存文件。复用 Spring、Spring Data Redis 和存储官方 SDK，不自写连接协议、分布式锁或对象存储服务。

## 实现采用的默认值与取舍

| 项目 | 本稿建议 | 取舍 |
| --- | --- | --- |
| 群规模 | 每群最多200人 | 覆盖企业小组，约束事务内收件人扇出；更大群需另做容量设计 |
| 拉人规则 | 群主/管理员可直接添加同组织员工 | 普通成员暂不支持邀请审批或公开群链接 |
| 新成员历史 | 从本次入群事件开始可见 | 避免新成员自动获得此前文件与聊天内容 |
| 退群/移除 | 撤销在线历史和附件访问；重新入群仅看新入群后的内容 | 已下载到设备的内容无法远程收回 |
| 消息与文件保留 | 首版不自动删除已发送历史；未引用上传24小时清理；同步事件保留7天 | 不是“永久保留”承诺；上线前确认容量配额和历史保留策略 |
| 存储 | 私有 S3 兼容存储，供应商在部署时选择 | AWS S3 或已有兼容服务；不把文件塞进数据库/Redis |
| 原生后台消息 | 首版保证前台在线实时、回前台补拉 | APNs/FCM/厂商离线推送单列后续能力 |

以上为当前实现的默认规则；群人数、类型白名单、容量等由配置约束。50 MB 按 **50,000,000 字节**执行；大文件分片、音视频通话、跨组织、外部客户、全文搜索、撤回/编辑、端到端加密不纳入本稿 V1。

## 当前仓库证据

核对了 `pom.xml`、JWT 过滤器与 CurrentUser、租户路由/执行上下文、WebSocket 配置/鉴权/连接管理、EIP 通知适配器、用户管理接口、租户 Flyway 目录。现有 `/purchase/in/stock/{id}/upload` 是采购上架动作，**不是文件上传接口**；Excel 导入和 RAG 草稿也不是聊天附件服务。

现有 `multi` 业务门禁仍在 JWT 过滤器内，本设计不通过新聊天端点绕过门禁。旧开放 Issue 文档描述过改造前状态；本稿以当前源码为准。
